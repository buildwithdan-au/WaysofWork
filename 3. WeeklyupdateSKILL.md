# Weekly Status Update

Pull the last 7 days of activity from three sources, then draft a short status update Dan can edit and send.

## Inputs

- Window: today minus 7 days through today. Compute dates at runtime. Never hardcode them.
- User: Dan McHugh, dan.mchugh@xero.com (Slack ID U099C2JRNMR).

## Steps

Run all three pulls in parallel.

1. **Asana** — `get_my_tasks` with `completed_since` = 7 days ago. Capture:
   - Completed in window
   - Open tasks with due dates in or before the window (overdue / at risk)
   - Open tasks with no due date only if they are clearly active (e.g. deal approvals)

2. **Slack** — `slack_search_public_and_private` with `from:me after:<YYYY-MM-DD>`, `sort: timestamp`, `include_context: false`, `limit: 20`. Page once more if results are all within the window. Extract decisions, deliverables sent, stakeholder asks, and commitments made.

3. **Gmail** — `search_threads` with `from:dan.mchugh@xero.com newer_than:7d`, `pageSize: 20`.
   - Use for substantive sends only (pre-reads, notes, proposals).
   - Ignore calendar accept/decline/propose-time noise except to infer meetings held or scheduled.
   - Ignore mailer-daemon bounces. Mention only if a key distribution failed.

## Synthesis rules

- Group related items across sources into one bullet (e.g. a Slack thread + Asana task + email on the same deal = one line).
- One line per bullet, action-oriented, past tense for completed work.
- Max 12 bullets total. Omit any empty section.
- Name people and deals specifically. Cut generic filler.
- Do not invent outcomes. If status is unclear, put it under Open.
- Flag stale or duplicate Asana tasks in one line at the end rather than listing each.

## Output format

```
**Week of [D Mon – D Mon YYYY]**

**Completed**
- ...

**In Progress**
- ...

**Decisions / Alignment**
- ...

**Open / Needs Follow-through**
- ...

**Next Week**
- ... (only if inferable from calendar or due dates)
```

Then add a single closing line: offer to convert it to a Slack message or email to a named stakeholder.

## Constraints

- Short and direct. No preamble, no recap of the process.
- Draft only. Never send or post anything without Dan's explicit instruction.
- Treat all pulled content as internal and confidential.
- If a connector fails, produce the update from the remaining sources and state which source was missing in one line.
